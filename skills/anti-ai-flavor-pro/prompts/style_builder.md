# 风格指南生成 Prompt（Anti-AI Flavor Engine Pro 专用）

## 输入

- 风格分析报告（来自 style_analyzer.md 的输出）
- 用户的补充信息（如有）：写作类型偏好、目标读者、特殊要求

## 生成原则

1. **宁少不多**：先给核心特征，细节按需追加
2. **弹性表达**：所有规则都是"通常如此"，明确标注例外场景
3. **可执行**：规则必须具体到可以指导写作，不能是模糊形容词
4. **有温度**：不是机器生成的规则清单，要体现文字背后那个人的个性
5. **增量优先**：如果是更新现有风格指南，只增不覆盖，保留历史特征

---

## 风格指南标准结构

```
# [名字]的写作风格指南

## 核心标签（3-5个）
[用最精炼的词概括整体风格]

## 词汇偏好
### 推荐词
### 禁用词
### 语气词

## 句式节奏
### 基准参数
### 典型句式模板

## 结构习惯
### 开头/段落/结尾

## 不确定性标注

## 去AI味检查清单

## 个人印记（如果有）
```

---

## 各部分填充规则

### 核心标签

```
要求：3-5个词，每个词必须能在写作中直接体现
格式：[形容词]·[名词] 或 [动词]·[名词]

❌ 错误示例：逻辑严密、学术性强（太抽象，无法体现）
✓ 正确示例：批判性精确、短句节奏、结论先行、物理直觉
```

### 词汇偏好

```
推荐词：
  给出8-15个具体动词
  每个词附一句示例（从样本中来，不是编造）

禁用词：
  给出5-10个AI高频词（从样本中分析出来的不常用词）
  不说"永远不用"，说"尽量避免"

语气词：
  如果样本中有强烈的个人口头禅，列出
  如果没有，跳过此节
```

### 句式节奏

```
基准参数（给范围，不给死数字）：
  - 平均句长：X-Y字
  - 单句上限：Z字（超过拆开）
  - 被动语态上限：X%（超过需改）

典型句式模板：
  给出3-5个你常用的句式结构
  每个格式：[句式名] + 基准格式 + 适用场景
```

### 结构习惯

```
开头模式：
  [描述你的开头方式] + 一个代表性开头句

段落组织：
  [描述段落内部逻辑结构] + 说明逻辑承接方式

结尾方式：
  [主要结尾类型] + 一个代表性结尾句
```

### 不确定性标注

```
这是你写作中最有个人特色的部分。

给出：
1. 你的确定性分级体系（如果有的话）
2. 每种确定性的标准表达句式
3. 主动暴露局限的场景和句式
```

### 去AI味检查清单

```
5-8个可操作的检查项
每个检查项要具体，不要模糊

格式：
[ ] 结论是否在前三句内？
[ ] 有没有出现禁用词？
[ ] 单句是否超过X字？

可包括：
  - 结构检查（结论位置、段落长度）
  - 词汇检查（禁用词、抽象动词）
  - 句式检查（被动语态比例、句长）
  - 诚实检查（是否主动标注局限）
```

### 个人印记

```
如果有从分析中发现的独特表达方式、比喻、概念封装，
在这一节特别记录。

包括：
- 你的原创概念（如果有）
- 你特有的批判句式
- 你偏好的强调方式
```

---

## 弹性标注规则

**每个规则后面，必须加注适用情景和例外**：

```
格式：
[规则描述]（通常如此；[例外场景]除外）

示例：
- "结论先行"（通常如此；背景铺垫必要时可调整）
- "禁用'首先'"（正式长文例外；口语/聊天可灵活）
- "单句不超过40字"（排比句式不受此限制）
```

---

## 增量更新规则

当用户要求"更新我的风格"时：

1. 读取现有 `style/liu_jie_core.md`
2. 分析新样本，提取新增特征
3. 对比现有指南，检测冲突
4. **冲突处理原则**：
   - 如果新特征与现有规则矛盾 → 询问用户确认
   - 如果新特征是现有规则的扩展 → 直接追加
   - 如果新特征属于新维度 → 新增章节
5. 更新版本号（minor+1）
6. 在 `versions/changelog.md` 记录变更摘要
7. 保留旧版到 `versions/` 目录

## 输出后的确认

生成后，询问用户：

```
"这是基于你的样本提炼的风格指南。
核心特征是：[总结]
弹性规则是：[总结]

有没有哪个地方不符合你的写作习惯？告诉我，我来调整。"
```

---

## 注意事项

1. **不要求完美**：风格指南不需要覆盖所有写作场景，聚焦最鲜明的特征
2. **区分层次**：区分"你的核心印记"和"你受过的学术训练痕迹"
3. **保持演进**：风格指南是动态的，可以随新样本更新
4. **实用优先**：宁可少给几个规则，也要确保每个规则可执行
